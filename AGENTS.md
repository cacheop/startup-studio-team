# Working with this startup repository

Read the root README first, then follow the relevant topic summaries and their evidence links. Read [docs/FORMAT.md](docs/FORMAT.md) for the shared record conventions.

- Treat `TEMPLATE.md` files and records with `record_type: template` as reusable forms. Exclude them from evidence and progress counts.
- Treat `null`, empty tables, and header-only CSV files as unknown or unrecorded information. An empty metric cell does not mean zero.
- Separate the team's claims from the evidence you inspect. Cite file paths and observation dates for material conclusions.
- Distinguish planned work, completed work, and observed results. Use evidence and outcomes when assessing progress.
- Read contradictory findings and dated decisions before summarizing the current position.
- Report inaccessible sources and missing information explicitly. Use "no new evidence recorded" when the files support only that conclusion.
- When asked for a dated assessment, record the source commit, comparison period, and rubric if the requester supplied one. Keep proposed assessments separate from founder-authored conclusions unless asked to update them.
- When editing, update the relevant current summary and link to the detailed record. Preserve past results and explain corrections.

The repository starts without company data. Add facts only when the team supplies them or an identified source supports them.
